# B15：KAN 符号蒸馏 — 158 条可读公式 + 重训第二层，RankIC 保留 97.2%（IC 68.3%）

分析对象：B1 主 KAN（`[158,24,1]`，grid 5 / order 3 / ±3）。把 B4 已 snap 的 **158 个特征最强边
符号公式**（每个特征恰好一条边，冻结不再训练）作为第一层，替换掉的不仅是可读性诉求——原来整层
样条参数（158×24 条边）都被替换成 158 条闭式函数。只重训第二层（24→1 的同一
KANLayer），报告相对原 KAN 的 RankIC 保留比例。脚本：`scripts/run_b15_symbolic_distill.py`
（本仓库 feature/b15-symbolic-distill 分支），产物：`common/runs/kan/symbolic-distill/`。

**一句话结论**：把第一层压成 158 条人能读懂的公式（`0.600·sigmoid(1.557x−2.643)−0.056`
这种形式）后，测试集 **RankIC 只掉 2.8%**（0.02643 → 0.02570，保留 **97.2%**），但 **IC（Pearson）
只保留 68.3%**（0.01977 → 0.01351）。两者不矛盾：公式化把预测压得更温和（预测 IQR 几乎减半），
秩序几乎不变而幅度信息损失明显（见第 4 节）。三层必须分开说：**RankIC 层**几乎无损；**头部
（topk=30 组合）**在本区间蒸馏占优（净值 CAGR 13.59% vs 7.15%、净值回撤 −16.41% vs −34.08%）；
**全截面排序区分度**对照更强（10 组单调性 0.952 vs 0.782、long_short 日均 0.001168 vs 0.000618）。
完整表述见 3.1–3.4，**不得笼统写成「蒸馏优于原模型」**。

## 0. 方法与口径

- **第一层（冻结，非训练）**：对 158 个特征各取 B4 判定的最强边（边范数 L1 口径），其函数为
  `φ(x) = a·f(b·x+c) + d`，`f ∈ {x, x², x³, |x|, sgn·log(1+|x|), sin, sigmoid, tanh}`
  （与 B4 `symbolic_snap_edges.csv` 同一候选族与拟合口径），参数直接读自 B4 产物，不重新拟合。
  158 条公式按 `strongest_hidden` 汇入 24 个隐藏节点（每节点 1–17 条入边，24 个节点全部被用到）。
  第一层以 buffer 形式注册——**0 个可训练参数**。
- **第二层（重训）**：与原 [158,24,1] KAN 的第二层完全同构（KANLayer 24→1，grid 5/order 3）。
  重训后的可训练参数 = 24 条边 × 10 = **240**（对照整模型为 38,160）。
- **paired 对照**：同一脚本、同一 seed(42)、同一 `run_b1.train_torch` 路径训练一次**原样条 KAN**
  （第一层可训）。两个模型唯一的差异 = 第一层是冻结的符号公式还是可训样条。
- **选择与评分纪律**：early stop / 模型选择只看 valid；test 集每个模型**只评分一次**，未基于
  test 做任何选择。
- **训练配置**：照抄 `run_b1.py`（AdamW lr 1e-3 / wd 1e-4 / batch 4096 / max 200 epoch /
  patience 15，CUDA，seed 42）；未调任何新超参。
- **回测/分层层汇总**：`python scripts/run_b15_symbolic_distill.py --summary-only` 只读已落盘的
  `backtest_report.csv` / `layered.csv` / `pred.parquet` 生成 `backtest_layer_compare.json`，
  不进入训练路径（本报告第 3–4 节即由此产出）。

### 3.1 口径核实：逐字段标注 `metrics.json` 的 `backtest` 真实含义

源头 `scripts/run_b1.py:210-211`（**已在 #32 修正**）：第 210 行对**超额**序列
`report["return"] − report["bench"]` 调 qlib `risk_analysis`（默认 `freq="day"` → **N=238**、
`mode="sum"`），原第 211 行又把 `annualized_return` **覆盖**成
`risk_analysis(report["return"]).iloc[0, 0]`，即**绝对**序列的第一行 `mean`。于是同一个字典里混了
两条序列，且字段名与值不符。本报告的核实对象是修正前的历史产物，这些磁盘产物的字段已改名（下表
左列即现名）：

| `metrics.json` 字段 | 真实含义（不是字段名字面） | 依据 |
|---|---|---|
| `mean` | **超额**收益（`return − bench`，bench = SH000300）日均 | run_b1.py:210 → risk_analysis(超额) |
| `std` | 超额收益日标准差（ddof=1） | 同上 |
| `information_ratio` | 超额 `mean/std × √238`（qlib 日频 **N=238，不是 252**） | evaluate.py:53/85；复算吻合 0.918102 / 0.362998 |
| `annualized_return`（磁盘产物已改名 `abs_daily_return_mean`） | **绝对收益 `return` 的日均值**——修正前字段名与值不符，既不是年化也不是超额口径 | 修正前 run_b1.py:211（`.iloc[0,0]` = 第一行 `mean`） |
| `max_drawdown` | **超额收益的算术累计回撤** `(cumsum − cumsum.cummax()).min()`，**不是**净值百分比回撤 | evaluate.py:70（`mode="sum"`） |
| `daily_turnover_mean` | 逐日 `report["turnover"]` 均值 | run_b1.py:212 |

**同一错命名是项目级的**（不是 B15 独有）：`common/scripts/run_baselines_builtin.py:86`、
`run_alpha158_lgb.py:118`、`run_alpha158_lgb_repro2017.py:101`、`run_master.py:132`、
`run_master_gate.py:163`、`run_master_repro2017.py:133`、`run_kronos_zs.py:151`、`run_prism_eval.py:65`，
以及 Track B 的 `run_b1.py:211` / `run_b8_csi500.py:228` / `run_b10_hybrid.py:489` /
`portfolio_attr.py:121`。反例是 `common/scripts/wp5_cost.py:40`，它用
`risk_analysis(r).iloc[:,0]["annualized_return"]` 取的是**真**年化行——修正前项目内两种写法并存。

**修正已落地**（#32）：上述 12 处已统一为 `wp5_cost.py:40` 的写法，此后新跑实验的
`annualized_return` 是**绝对（组合）年化** `mean × 238`（同字典其余字段仍是超额口径，差异见上表）。
历史产物的旧字段已在磁盘上改名为 `abs_daily_return_mean`：65 个 `metrics.json` / `summary.json`
（`common/runs/` 下，含 B1/B8/B10/B12/baseline/hybrid/symbolic-distill 等）与
`portfolio-attr/sens_matrix.csv` 表头；`wp5_report/cost.json` 本就由正确写法产生（值是真年化），未动。

**净值曲线必须用 `account` 列**：`backtest_report.csv` 的 `value` 是持仓市值、`cash` 是现金，
**两者之和才是组合总资产**（已用 `allclose` 验证 `value + cash == account`）。净值曲线与百分比回撤
必须基于 `account`；若误用 `value` 列会得到错误回撤（本实验 distilled：account 口径 −16.41% vs
只取 value 的 −18.61%）。另外 `return` 是 qlib 的
`return_rate = (now_earning + now_cost) / last_account_value`（`backtest/account.py:283`），是**持仓
视角**的收益率而非账户复合收益率——所以 `(1 + return).prod() − 1`（0.672 / 0.361）**不等于**真实账户
增长（0.585 / 0.283）。这就是为什么 CAGR 必须从 `account` 复利算出，不能拿 `return` 列连乘。

### 3.3 内部张力：RankIC 保住 97.2%，为何全截面分层指标反而下降？

答案在于**两个组合消费的排序信息量不同**：`TopkDropout(topk=30)` 只看每日预测最顶部的 30 只，
只要**头部相对次序**稳定就够；而 10 分组单调性与 `long_short` 需要**全截面**（中段 + 两端）的
排序分辨力。三层如实并列：

| 层面 | 口径 | 蒸馏 | 对照 | 谁占优 |
|---|---|---|---|---|
| 全局秩相关 | test RankIC | 0.025696 | 0.026425 | 几乎持平（保留 97.2%） |
| 头部（topk=30 组合） | 净值 CAGR | 13.59% | 7.15% | **蒸馏** |
| 头部（topk=30 组合） | 净值最大回撤（%) | −16.41% | −34.08% | **蒸馏** |
| 头部（topk=30 组合） | 绝对 IR（×√238） | 0.9186 | 0.5529 | **蒸馏** |
| 全截面排序 | 组间单调性 | 0.782 | 0.952 | **对照** |
| 全截面排序 | long_short 日均 / IR（日均） | 0.000618 / 0.046 | 0.001168 / 0.094 | **对照** |
| 尾部（g0，预测最低十分位） | 组均收益 | +0.000006 | −0.000353 | **对照** |
| 头部十分位（g9） | 组均收益 | 0.000624 | 0.000815 | **对照** |

注解（全部基于已有数字，无新实验）：

1. **头部选择质量保住甚至更好，全截面分辨力下降，二者不矛盾**。蒸馏在 topk=30 口径全面占优
   （CAGR 13.59% vs 7.15%、绝对 IR 0.9186 vs 0.5529、净值回撤 −16.41% vs −34.08%），说明它**选出
   头部好股票**的能力没丢；但 10 分组要区分全截面，中段与两端都算在内，蒸馏在这一层输。
2. **尾部是损失最明显的一端**：g0 从 −0.000353 抬到 **+0.000006**（几乎等于截面均值，等于
   "排不出差股"），g9 从 0.000815 降到 0.000624。`long_short = g9 − g0` 因此几乎腰斩——
   底部抬得比顶部降得更狠，是 long_short 变差的主因。
3. **刚性公式压缩了预测的动态范围（直接证据）**：蒸馏预测 std 0.0472 vs 0.0781（**−40%**）、
   IQR 0.0597 vs 0.0878、日度截面极差均值 0.263 vs 0.492（**约减半**）。每特征只保留一条边，
   第一层输出幅度小于原 24 条边求和；第二层只能在其基础上重标度，**无法恢复已丢的幅度信息**。
   幅度被压缩后两端被"卷"向中段，decile 分离度下降——这解释了为何全局秩相关（RankIC）几乎
   不动，而依赖幅度的全截面指标掉得明显。
4. 次要机制（作用小、方向一致）：预测更温和 → 排序更稳定 → 换手更低（0.0631 vs 0.0688）、
   成本更低（6.26e-5 vs 6.83e-5），对 topk-30 净收益有利。但主因是上一条，且净值上的优势
   （+58.5% vs +28.3%）数值虽大，仍只是**单一窗口**的观测。

### 3.4 结论口径与限定（禁止笼统表述）

- 允许的表述：**「IC（RankIC）层几乎无损（97.2%）；头部（topk=30）组合指标在本区间蒸馏占优；
  全截面排序区分度（10 组单调性、long_short）有损失」**。
- 禁止的表述：「蒸馏优于原模型」「公式化无损」「可读公式完全替代样条」——三者都跨了层面。
- **所有差异均为单一 test 区间（2023-01-03 ~ 2026-07-23，860 交易日）与单 seed（42）下的观测**；
  B7 测得 KAN 的 test RankIC 种子 std ≈ 0.0027，与这里的分层差异同阶。净值口径的 15 个百分点差距
  在单窗口下同样不能外推。
- 组间单调性两模型都非完美单调，与 README 记的「Alpha158 在 2023+ regime 弱化」一致。

## 4. IC 与 RankIC 保留率背离的解释

同一批预测，RankIC 保留 97.2% 而 IC 只保留 68.3%，而头部（topk=30 组合）在本区间反而是蒸馏占优
（净值 CAGR 13.59% vs 7.15%）。基于**已有数字**（不新增训练实验）的解释（全截面/头部的完整
拆解见 3.3，此处聚焦 IC 与 RankIC 这一对）：

1. **两个指标的敏感度不同**：RankIC（Spearman）是秩相关，对预测做任何单调变换都守恒——公式化
   保留了两两相对秩序，故 RankIC 几乎不动。IC（Pearson）是线性相关，直接受预测幅度与极值影响。
2. **符号公式把预测压温和了**（有直接证据）：蒸馏预测 std 0.0472 vs 对照 0.0781（**−40%**）、
   IQR 0.0597 vs 0.0878（−32%）、日度截面极差均值 0.263 vs 0.492（**约减半**）。每特征只剩一条
   边，第一层输出幅度小于 24 条边求和，第二层只能在其基础上重标度、**无法恢复已丢的幅度**。
   幅度是 IC 的分子，因此 IC 掉得多。
3. **与分层结果自洽**：long_short 取两端 decile，压温和的预测使两端被“卷”向中段——g0 由
   −0.000353 抬到 +0.000006、g9 由 0.000815 降到 0.000624，于是 long_short 日均（0.001168 →
   0.000618）与组间单调性（0.952 → 0.782）同步走弱，与“IC 损失来自极值、而非中段秩序”一致。
4. **头部组合不受同一损伤，故反向有独立机制**：`TopkDropout(topk=30)` 只看头部极少数的
   相对次序，不需要全截面（含两端）的幅度分辨力；叠加预测更温和 → 排序更稳定 → 换手更低
   （0.0631 vs 0.0688）、成本更低（6.26e-5 vs 6.83e-5）。所以两个层面不矛盾：**一个吃全截面
   幅度分辨力（IC / decile 多空），一个只吃头部排序稳定性（RankIC / topk 组合）**。

需要克制的地方：第 4 点的证据（净值 CAGR 13.59% vs 7.15%、超额 IR 0.918 vs 0.363）叠在单窗口
单 seed 上，且超额 IR 的分子（日均超额收益）是本报告噪声最大的量；它只能算与机制一致的
观察，不能当成结论，更不能反过来当作「蒸馏更好」的证据。

## 6. 限定与风险

- **保留率是单 seed、单 test 区间结果**。对照与蒸馏都用 seed 42，test 区间单一（2023-01-03 ~
  2026-07-23）；B7 已量化 KAN 的 test RankIC 种子 std ≈ 0.0027，≥ 本次差值 0.0007，即 97.2% 这个
  点估计的置信区间会跨过 100%。「公式化几乎无损」成立，但不得写成「蒸馏优于原模型」。
- **结论口径分层**：RankIC 保留 97.2%、IC 保留 68.3%、long_short 日收益保留约 53%；**头部
  （topk=30）组合指标在本区间蒸馏占优，而全截面排序区分度对照更强**。引用时必须写明是哪个
  口径；「无损」只在 RankIC 口径下成立，不得写成「蒸馏优于原模型」。
- **`metrics.json` 的 `backtest` 混用两条序列**（见 3.1，逐字段表）：`mean`/`std`/
  `information_ratio`/`max_drawdown` 是**超额**口径，修正前名为 `annualized_return` 的字段实为
  **绝对收益的日均值**（既非年化也非超额）。同一错命名曾在 `common/scripts/run_baselines_builtin.py:86`
  等 12 处重复（反例 `wp5_cost.py:40`）；**已在 #32 统一修正**，历史产物的该字段已改名为
  `abs_daily_return_mean`。引用修正前的旧产物时必须按字段表核对真实含义，不得采信旧字段名。
- **净值与回撤必须用 `account` 列**（= `value` + `cash`）；用 `value` 会得到错误回撤（−18.61% vs
  −16.41%）。且 `(1+return).prod() − 1` ≠ 账户增长（0.672 vs 0.585），CAGR 必须从 `account` 复利算。
- **年化有两个并存口径**：qlib `mode="sum"` 的算术 `mean × 238` 与 `account` 净值的几何 CAGR；
  引用时必须写明用哪个，勿与 √252/√242 混用（本报告 IR 统一为 √**238**，已数值逐位验证）。
- **第一层被替换的是「每特征一条最强边」**。原 KAN 第一层每特征有 24 条边，B15 只保留最强的
  一条（其余边不存在），因此本实验同时验证了两件事：最强边承载了主要信号、且多边冗余度很高。
- valid 差距（−0.0073）远大于 test 差距（−0.0007）：若用 valid 指标讲故事，损失看起来会大得多；
  test 上的 97.2% 才是「部署性能保留」的读数——但同样只在 RankIC 口径下成立。
- 第一层「0 可训练参数」由 `n_params=240`（仅第二层）证实。
